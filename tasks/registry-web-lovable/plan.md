# 执行计划

本计划属于 [Registry 父任务](packet.md)，只拥有推进顺序，不另建任务控制入口。

## 01 方案与授权（完成）

Sir 已确认 CPython / Neon 方向并授权实施。采用 Tortoise 的异步 ORM、asyncpg 和内置迁移，独立内部主键配合业务唯一约束；FastAPI / Jinja 与 boto3 在同一 CPython 服务中运行。当前部署实现使用 OCI / Heroku，Registry 拥有独立 Neon 项目和 R2 存储权限。Sir 已重新确认完整部署方案与普通应用角色、文件缓存调整，要求使用 Heroku Eco dyno。

不引入 Django、不自写模板渲染器，不恢复 D1 手写业务 SQL，不复制生产数据到预览。生产切换采用明确的暂停写入、最终快照、导入核验和切流窗口，不建设双写同步系统。长期事实已经写入源码和 Unit / Deployment 文档。

## 02 服务实现与本地验收（完成）

实现已覆盖连接生命周期、ORM 关系和事务、状态锁、S3 staging 与流式读取、GET / HEAD、单一容器入口、运维凭据和 D1 导入。公开契约和现有视觉资源保持不变。真实 Neon 发布流程与临时 D1 快照导入分别通过。

最终本地 `pnpm check` 已通过。PostgreSQL 17 CI 与完整容器构建由同一提交的 PR checks 记录；交付前必须确认其结果。真实数据库的失败回滚、并发冲突、私有分页、blocked 读取和导入保真必须继续通过；旧 Worker 的通过结果不能替代它们。

## 03 迁移演练、远程预览与 PR（进行中）

1. 完成最终检查后提交并推送 Registry 与配套治理变更，更新 PR 描述，以最终 CPython / Neon 实现为准。分别保留各仓库的提交边界。
2. 完成 Eco、数据库角色和缓存调整；Heroku、Cloudflare 和 Neon 的 preview 控制凭据已配置并验证。本地 Docker / Colima 已就绪，用仓库现有 Dockerfile 和可信控制器进行首次 pre-merge 远程验收。
3. 用同一镜像迁移和部署 PR 33，核验空目录、详情 / Publisher、公开读取与认证、文件协议及重新部署保留数据。完整发布数据仅在一次性数据库和桶内生成并清理，不把验收 fixture 固化到共享预览。
4. 核验清理控制器仅能停止和删除对应 closed PR 的 app、branch、bucket 及对象凭据；记录实际来源 SHA、镜像和 URL。没有远程实证的部分继续标记未验证。
5. 完善 `production-registry.md` 的切换操作，明确真实 D1 来源、目标库、保全点、写入暂停、最终导入、切流及失败恢复条件。新库接收写入后不能把旧 Worker 回退当作无损恢复。

## 04 获准切换并关闭父任务（等待远程验收与生产授权）

在完整操作可审阅后取得生产资源变更与切流授权。按获准方案保全来源、停止旧写入、导入并核验、切换公开路由、恢复新写入；验证实际消费者和分发内容。

旧 D1 / Worker 按明确保留窗口处理，删除另需授权。只有代码、生产行为、文档和跨仓库约定一致且父任务实际验收后，才清理整个 packet；不因某个子步骤或 PR 完成就删除它。
